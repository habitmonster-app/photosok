아래 프로젝트를 새 시안으로 다시 만드는 것이 아니라, 현재 소스를 기준으로 이어서 완성해 줘.

프로젝트: 사진쏙 v1.5
목적: 사진·PDF를 제출하거나 공유하기 전에 용량·크기·페이지를 정리하는 모바일 유틸리티.
사용자의 목표: Puma, Smallpdf 같은 기존 앱을 두고도 우리 앱을 사용할 이유가 있는 실제 제품. 추상적 실험보다 성능과 완성도가 중요함.

먼저 할 일
1. 첨부 문서와 실제 dist/ 코드를 읽고 구현된 것, 아직 없는 것, 확인이 필요한 것을 구분해 줘.
2. 전체 ZIP을 사용할 수 있으면 압축을 풀고 run_local.py로 실행해 줘. 별도 npm 설치나 빌드는 필요 없어.
3. 02_TECHNICAL_HANDOFF_KO.md와 tests/README_KO.md에 따라 기본 동작을 확인해 줘.
4. 다음 우선순위는 모바일 저장·공유·파일 선택, 오류 복구, 대용량 처리 안정성, PDF 가독성이야. 우선 재현되는 문제부터 수정하고 변경 파일과 확인한 결과를 보여 줘.

현재 핵심 기능
- JPG/PNG/WebP 압축·크기·형식 변환, 목표 바이트 확인, 정확한 픽셀 규격, 결과 비교, 일괄 저장
- 기존 PDF+사진 혼합, 페이지 정렬/삭제/회전, 글자 유지 합치기 또는 이미지화해 전체 용량 맞추기
- 수동 네 모서리 보정/자르기, HEIC 기본 디코딩 및 로컬 Worker 대체 처리
- 지원 환경의 저장 위치 선택, 비지원 환경의 다운로드/파일 열기/공유 안내
- 원본 보존, 로컬 파일 처리, 기존 결과 재사용, 취소·실패 시 이전 결과 유지

유지할 기준
- 현재 디자인·문구는 독자 표현으로 v1.5에서 변경했어. “보내기 전에, 사진쏙.”이라는 이용 목적을 유지해 줘.
- 사용자 파일은 서버에 업로드하지 않아. 외부 전송이나 계정/클라우드 보관을 임의로 추가하지 마.
- “PDF 용량 맞추기”는 텍스트를 이미지화하고, “글자 유지”는 목표 용량을 보장하지 않아. 이 차이를 숨기지 마.
- 브라우저가 다운로드를 요청한 것을 실제 저장 완료라고 단정하지 마.
- OCR, 자동 테두리 인식, 앱스토어 출시, 실기기 QA가 완료됐다고 말하지 마.
- 경쟁사보다 빠르거나 좋다는 직접 비교 수치는 아직 없어. 동등한 조건에서 측정하기 전에는 그런 홍보 문구를 쓰지 마.
- 오픈소스 출처와 라이선스는 유지해 줘. HEIC/HEVC·폰트·상표 관련 권리 검토도 아직 완료되지 않았어.
- 프레임워크 전체 교체나 기능 대량 추가보다 현재 구현의 안정성과 쓰기 쉬운 흐름을 먼저 완성해 줘.

보고 방식
무엇을 실제로 수정했는지, 어떤 환경에서 확인했는지, 무엇이 아직 확인되지 않았는지를 구분해서 알려 줘.
배포/과금/네이티브 앱 전환은 현재 확정된 사항이 아니야. 선택이 필요하면 장단점과 추천안을 구체적으로 보여 줘.

첨부 TXT만 받은 경우
이 TXT에는 대화 요약과 주요 자체 소스가 들어 있어. 외부 라이브러리 바이너리와 모든 테스트는 ZIP에 있어.
TXT만으로 전체 실행 파일을 확보했다고 가정하지 말고, 읽을 수 있는 코드 검토를 먼저 진행해 줘.
ZIP이나 풀어 놓은 프로젝트에 접근할 수 없는 경우 필요한 파일만 정확히 짚어 줘.
